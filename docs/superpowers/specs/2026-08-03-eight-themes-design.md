# MD 阅读助手八套主题设计规格

日期：2026-08-03  
状态：已确认并实施

## 1. 目标

在不改变现有阅读、编辑、窗口和文档功能的前提下，将当前“浅色 / 深色”二选一升级为 8 套完整配色主题。主题应同时作用于阅读页、实时预览、Markdown 编辑器、语法高亮、侧栏、弹窗和菜单，并在重启应用后保持用户选择。

## 2. 方案比较

### 方案 A：8 套完整配色主题（采用）

每套主题独立定义背景、纸张、正文、次要文字、边框、强调色、代码区和语法高亮色。优点是完成度高、每套主题辨识度明确，且能控制长时间阅读的舒适度；代价是需要维护一组完整 CSS 变量。

### 方案 B：浅色 / 深色基底加 6 个强调色

只替换按钮、链接和选中状态颜色。实现较简单，但页面主体几乎不变，无法形成用户期望的“主题”体验，因此不采用。

### 方案 C：基底模式与强调色自由组合

允许用户分别选择浅色 / 深色和强调色。自由度最高，但会产生大量未经设计验证的组合，设置界面也更复杂，不符合当前产品轻量、克制的定位，因此暂不采用。

## 3. 最终主题清单

| 主题 ID | 中文名称 | English | 模式 | 设计方向 |
|---|---|---|---|---|
| `classic-light` | 经典浅色 | Classic Light | 浅色 | 保留当前温润纸张风格，作为默认主题 |
| `classic-dark` | 经典深色 | Classic Dark | 深色 | 保留当前低眩光深色主题 |
| `wechat-green` | 青翠新语 | Verdant Voice | 浅色 | 以清晰、亲和的鲜绿色作为强调色，避免直接复制品牌界面 |
| `alipay-blue` | 云海湛蓝 | Azure Cloud | 浅色 | 明快科技蓝，适合技术文档和效率工作场景 |
| `wisteria` | 紫藤雾色 | Wisteria Mist | 浅色 | 柔和紫灰纸张，精致但不过度艳丽 |
| `amber-paper` | 琥珀书页 | Amber Paper | 浅色 | 温暖复古纸张感，适合长篇阅读 |
| `deep-ocean` | 深海夜航 | Deep Ocean | 深色 | 深蓝灰低眩光背景，强调代码阅读 |

## 4. 配色结构

现有 CSS 变量继续作为唯一主题接口，每个主题至少定义：

- 页面：`--bg`、`--panel`、`--paper`、`--paper-strong`
- 文字：`--text`、`--muted`、`--faint`
- 结构：`--line`、`--shadow`
- 强调：`--green`、`--green-deep`、`--green-soft`
- 代码：`--code` 及现有全部语法高亮变量

不在组件中直接写主题专属颜色。所有新增主题都通过根节点的 `data-theme` 属性覆盖变量，以保证阅读页、预览区和 CodeMirror 编辑器一致响应。

初步强调色方向：

- 青翠新语：`#07C160`，搭配低饱和浅绿背景和深绿文字
- 云海湛蓝：`#1677FF`，搭配低饱和浅蓝背景和深蓝文字
- 紫藤雾色：`#765B7E`
- 琥珀书页：`#986536`
- 深海夜航：`#70A9BD`
- 墨夜紫晶：`#B39AC0`

具体正文、边框和语法色在实现时以可读性和对比度为准微调。

## 5. 主题选择交互

顶部现有主题按钮不再只执行明暗切换，点击后打开主题面板：

- 面板采用 2 列 × 4 行的小型主题卡片布局。
- 每张卡片包含配色圆点、主题名称和当前选中标记。
- 中文界面显示中文名称，英文界面显示英文名称。
- 鼠标悬停显示该主题的纸张与强调色预览。
- 点击主题立即生效并关闭面板，不需要额外“保存”按钮。
- `Escape`、点击面板外部或再次点击主题按钮可关闭面板。
- 按钮的图标颜色随当前主题变化，并提供中英文 `title` / `aria-label`。

不新增独立设置页面，保持工具栏简洁。

## 6. 状态、持久化与兼容

- 前端状态由 `state.theme` 保存主题 ID，不再使用单一 `state.dark` 布尔值作为主题真相源。
- `localStorage.theme` 保存主题 ID。
- 兼容旧值：`light` 自动迁移为 `classic-light`，`dark` 自动迁移为 `classic-dark`。
- 缺失、未知或损坏的主题值回退到 `classic-light`。
- 主题在应用初始化早期恢复，尽量避免启动时从浅色闪烁到深色。
- 原生窗口仍通过现有 `window.leafMD.setTheme(dark)` 接口同步；主题注册表为每套主题声明 `mode: light | dark`，深色主题传 `true`，浅色主题传 `false`。
- Go 后端接口无需改变，降低跨平台风险。

## 7. 实现边界

预计修改：

- `frontend/index.html`：增加主题选择面板结构。
- `frontend/src/renderer.js`：主题注册表、迁移、选择、持久化和中英文名称。
- `frontend/src/styles.css`：8 套变量、主题面板和响应式样式。
- `frontend/tests/`：主题注册、迁移、持久化和深浅模式映射回归测试。
- `README.md`、`README.en.md`、`CHANGELOG.md`：补充多主题功能说明。

本功能不修改文档内容、最近阅读、自动保存、窗口尺寸、字号缩放和文件系统逻辑，也不引入新框架或第三方依赖。

## 8. 可访问性与质量要求

- 正文和主要控件应达到 WCAG AA 常规文字对比度目标。
- 不能只依靠颜色表达选中状态；选中卡片同时显示勾选图标或明确边框。
- 键盘可以聚焦并选择所有主题卡片。
- 阅读区、实时预览和编辑器必须同步切换，不能出现一半旧主题、一半新主题。
- 弹窗、下拉菜单、搜索面板、代码块和滚动条必须跟随主题。
- 打印样式继续使用适合纸张的浅色输出，不受当前深色主题影响。

## 9. 验证标准

1. 8 套主题均可从工具栏选择并即时生效。
2. 重启应用后恢复最后选择的主题。
3. 旧版保存的 `light` / `dark` 值正确迁移。
4. 未知主题值安全回退到经典浅色。
5. 3 套深色主题同步启用原生深色窗口；5 套浅色主题同步启用原生浅色窗口。
6. 中英文界面显示对应主题名称和辅助文字。
7. 阅读模式、左右分栏编辑、搜索、弹窗、菜单、目录与资源浏览器的颜色一致。
8. 字号缩放、面板宽度记忆、编辑自动保存和现有快捷键不受影响。
9. 前端测试、生产构建、Go 测试、`go vet` 和 `git diff --check` 全部通过。
