# 编辑器字号缩放设计

## 目标

现有“放大文字”“缩小文字”“恢复字号”和 `Ctrl/Cmd +`、`Ctrl/Cmd -`、`Ctrl/Cmd 0` 只改变 Markdown 阅读与预览区域。调整后，同一缩放比例还要作用于右侧 CodeMirror 编辑器，使 4K 显示器上的源码、Markdown 语法高亮和行号清晰可读。

## 交互规则

- 阅读页正文、编辑页左侧实时预览、右侧编辑源码和行号使用同一个缩放比例。
- 缩放范围从现有的 82%–135% 扩大为 82%–200%，每次仍增减 8%。
- “恢复字号”恢复到 100%。
- 缩放值继续保存到 `localStorage.fontScale`，应用重启后自动恢复。
- 缩放不得重新创建编辑器，不得改变当前光标、选区、滚动位置和撤回历史。
- 工具栏、搜索面板、窗口菜单等界面控件保持原有大小，避免整体布局被放大破坏。

## 实现方案

保留现有 `state.fontScale` 和根元素 CSS 变量 `--font-scale` 作为唯一状态源。在 CodeMirror 主题根节点上使用 `calc(15px * var(--font-scale))`，使编辑器正文、语法高亮和行号通过 CSS 继承同步缩放。`setFontScale` 只负责限制范围、更新变量和持久化，不重新配置或重建 `EditorView`。

该方案比重建 `EditorState` 或动态派发主题配置更简单，也不会干扰编辑器的撤回安全边界。

## 测试与验收

- 回归测试确认最小值为 82%、最大值为 200%、默认值为 100%。
- 回归测试确认 CodeMirror 主题使用同一个 `--font-scale`，而不是独立字号状态。
- 验证菜单按钮和三个快捷键仍调用同一缩放函数。
- 执行前端生产构建、Go 测试、`go vet` 和 `git diff --check`。
- 人工验收时进入编辑模式，连续放大后确认左侧预览、右侧源码和行号同步变大；切换文档及重启应用后比例仍保留。
